# tele v1.2.0

This release makes Linux a supported platform and closes the secret-custody gap
without weakening macOS behavior.

- adds the portable authenticated `vault-v1` backend on macOS and Linux, with
  controlling-TTY, protected-file, and inherited-FD unlock paths
- adds functional Linux `secret-service-v1` support with typed missing,
  headless, and locked-provider failures
- replaces the legacy macOS Keychain layout with the native, catalog-backed
  `keychain-v1` implementation and a verified compatibility migration
- makes backend selection explicit and sticky, with full-catalog verified
  migration, retained sources, diagnostic receipts, and exact-instance purge
- follows Linux XDG config, data, and runtime paths while detecting ambiguous
  legacy/XDG state instead of guessing
- reconciles managed bots against Telegram's remote catalog and preserves
  explicit tombstone, import, and token-custody semantics
- adds `tele update --check` and the explicit `tele update --yes` path for
  unambiguous writable Go installations, with candidate config/vault preflight,
  exact version verification, and same-directory rollback; Homebrew and
  standalone installs receive safe exact recommendations
- ships cgo-free macOS and Linux arm64/amd64 archives, verifies static Linux
  linkage and an Alpine runtime, and keeps Windows as compile-smoke only

The existing `tele/v1` command and machine-output namespace remains stable. New
secret-management, reconciliation, doctor, and updater results are published in
the versioned schemas.
