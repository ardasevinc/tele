# tele v1.2.4

Tele now tunnels its Telegram MTProto connections through an HTTP CONNECT
proxy when one is configured. It reads `TELE_HTTP_PROXY`, then `HTTPS_PROXY`
and `HTTP_PROXY` (either case), then `SAND_EGRESS_TUNNEL_PROXY_ADDR` as a bare
`host:port`. Basic proxy credentials in the URL are supported. Non-`http`
proxy schemes fail with a clear error instead of falling back to a direct
connection.

This fixes `context deadline exceeded` during `tele auth start` and normal use
on sandboxed Linux hosts whose transparent egress path breaks direct
connections to Telegram data centers. With no proxy variables set, connection
behavior is unchanged. Credential storage, Keychain policy, and command
contracts are unchanged; no migration is needed from 1.2.3.
